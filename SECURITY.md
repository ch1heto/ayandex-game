# Security Policy — Ashvale

Этот документ обязателен для всех изменений в проекте. Он дополняет `AGENTS.md`, `GAME_DESIGN.md` и `docs/yandex-games-requirements.md`, но не заменяет их.

## Граница доверия

- Браузерный клиент считается недоверенным: игрок может изменять JavaScript, память, локальное хранилище, сетевые запросы и их ответы.
- Клиент отвечает только за отображение и локальный ввод. Он не является источником истины для прав на товары, платежей, наград, валюты, прогресса или иных ценных состояний.
- Любая будущая серверная или платформенная интеграция должна проверять данные и права независимо от клиента.

## Секреты и конфигурация

- Нельзя добавлять в клиентский код, Vite-переменные, репозиторий или production bundle API keys, secrets, приватные ключи, пароли, refresh tokens и иные долговременные токены.
- Публичные идентификаторы приложения не считаются секретами, но должны иметь минимально необходимые права.
- Секреты, нужные серверной части, хранятся только вне клиентского репозитория и не передаются в браузер.

## Сохранения и данные пользователя

- Все save data, включая данные из `localStorage`, Yandex Player и импортируемых файлов, считаются недоверенными.
- Перед чтением и применением сохранения необходимо проверять схему, типы, версию, обязательные поля, диапазоны чисел и ссылочную целостность идентификаторов.
- Некорректные, устаревшие или повреждённые данные не должны ломать игру: используйте миграцию, безопасные значения по умолчанию или контролируемый отказ.
- Не передавайте персональные данные в сохранениях без отдельной необходимости, правового основания и документированной политики обработки.

## Безопасный код и DOM

- Запрещены `eval`, `new Function` и `document.write`.
- Не используйте `innerHTML` с непроверенными данными. Для текста используйте `textContent`; HTML допустим только из статического, проверенного исходника.
- Данные из URL, query string, hash, `postMessage`, формы, сохранения и внешнего API валидируются до использования.
- Сообщения `postMessage` принимаются только от ожидаемых origin, с проверкой структуры сообщения и его типа. Никогда не доверяйте полям `event.data` без валидации.
- URL для переходов, загрузок и запросов проходят проверку схемы, origin и ожидаемого формата; не используйте непроверенные URL как `href`, `src` или сетевой endpoint.

## Сеть и внешние ресурсы

- По умолчанию игра использует локально упакованные ассеты и не зависит от сторонних ресурсов.
- Внешние запросы разрешены только к предварительно утверждённым HTTPS/WSS-хостам. Запрещены `http`, `ws`, IP-адреса и произвольные URL из данных клиента.
- Каждый новый внешний хост должен быть обоснован, внесён в настройки Яндекс Игр и проверен на совместимость с CSP до релиза.
- Ошибки сети не должны раскрывать секреты или внутренние детали реализации пользователю.

## Yandex Games и платежи

- Весь код взаимодействия с Yandex Games SDK размещается в `src/yandex/`; сцены и игровые системы не вызывают SDK напрямую.
- Реклама, покупки, авторизация, сохранения и платформенные lifecycle-события проходят через типизированные адаптеры в `src/yandex/`.
- Покупка не считается подтверждённой только по локальному состоянию клиента, callback UI или обещанию браузера. Подтверждение и выдача ценности требуют проверки через доверенный платформенный/серверный источник, когда такая интеграция появится.
- Встроенные платежи и реклама используют только поддерживаемые механизмы Yandex Games SDK.

## Зависимости и цепочка поставки

- Перед добавлением npm dependency проверяйте назначение пакета, репутацию, лицензию, поддерживаемость, транзитивные зависимости и необходимость для проекта.
- Фиксируйте зависимости в `package-lock.json`; не используйте непроверенные install/postinstall-скрипты.
- Регулярно запускайте аудит зависимостей и обновляйте уязвимые пакеты после оценки совместимости.

## Production build и релиз

- Production build не должен содержать debug UI, тестовые команды, dev-only обходы, подробные stack trace, секреты или source maps.
- Source maps отключаются для production-артефакта и не включаются в публикуемый ZIP.
- Перед релизом проверяйте содержимое `dist/`, browser console, внешние запросы, CSP и соответствие требованиям Яндекс Игр.
- Публикуемый ZIP содержит корневой `index.html`, только разрешённые файлы и имена без пробелов и кириллицы.

## Минимальный security review

Перед merge или release изменений, затрагивающих сеть, сохранения, платежи, SDK, URL/`postMessage`, DOM или зависимости, проверьте:

1. Не появились ли секреты в исходниках, переменных окружения или bundle.
2. Валидируются ли все недоверенные входные данные.
3. Ограничены ли origin и HTTPS/WSS-хосты.
4. Изолирован ли Yandex SDK в `src/yandex/`.
5. Не доверяет ли код клиентскому подтверждению покупки или ценной награды.
6. Не попали ли в production debug-код и source maps.
7. Соответствуют ли изменения CSP и правилам Яндекс Игр.
